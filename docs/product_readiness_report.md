# プロダクトレベル（本番運用耐性）評価・批判的解析レポート

## 1. 概要
本レポートは、Goose-in-the-Box をプロダクトレベル（本番環境での長期運用・保守性・安全性を備えた状態）へ向上させるために実施した調査・静的解析・セキュリティ/コード品質レビューの結果および改善対応方針をまとめたものです。

---

## 2. 批判的解析（現状の課題と分析）

### A. FastAPI バックエンド (`control-panel/app/`)
1. **グローバル例外ハンドラの未実装 (HTTP 500応答の脆弱性)**:
   - 現状: 未予期の例外が発生した際、FastAPI のデフォルト 500 レスポンスや内部スタックトレースが露出するリスクがある。
   - 改善案: `main.py` に `Exception` キャッチのグローバルハンドラを実装し、統一された JSON エラー構造（`{"error": "Internal Server Error", "message_ja": "...", "message_en": "..."}`）を返す。
2. **セキュリティヘッダーの欠落**:
   - 現状: コントロールパネルのレスポンスに `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy` 等の HTTP セキュリティヘッダーが付与されていない。
   - 改善案: Response Middleware を追加し、全レスポンスに標準セキュリティヘッダーを自動付与する。
3. **ドメイン入力バリデーションの未強化**:
   - 現状: `whitelist.py` や `temp_whitelist.py` において、不正な形式のドメイン（改行文字、スペース、不正な特殊文字が含まれる文字列）に対する厳密な正規表現バリデーションが不足している。
   - 改善案: ドメイン形式検証ロジック（正規表現 `^[a-zA-Z0-9\.\_\-\:\*]+$`）を適用し、不当な文字列入力を拒否（HTTP 400）する。

### B. シェルスクリプト群 (`bin/*.sh`)
1. **依存コマンドの存在チェック欠落**:
   - 現状: `bin/watch-alerts.sh` や `bin/audit-tools.sh` などで `jq` や `curl` コマンドが未インストール環境で実行された場合、分かりにくいエラーが発生する。
   - 改善案: 必須コマンド（`jq`, `curl` 等）の事前チェックロジック（`command -v`）を共通化・導入する。

### C. ユニットテスト (`tests/test_control_panel.py`)
1. **例外ケース・セキュリティ機能のテスト不足**:
   - 現状: 不正ドメイン入力、未定義パスアクセス、セキュリティヘッダーの存在チェックなどがテストされていない。
   - 改善案: 新規追加したバリデーション、例外ハンドラ、セキュリティヘッダーに対するユニットテストを追加する。

---

## 3. 改善実施計画

1. `control-panel/app/main.py`: グローバル例外ハンドラとセキュリティヘッダーミドルウェアの実装。
2. `control-panel/app/whitelist.py` & `temp_whitelist.py`: ドメイン形式の厳密な正規表現チェックの実装。
3. `bin/*.sh`: 依存コマンド（`jq`, `curl`）の事前確認チェックの追加。
4. `tests/test_control_panel.py`: 追加機能および異常系テストケースの作成と全テスト合格の確認。
