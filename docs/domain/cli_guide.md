# CLI 使い方・運用ガイド

本ドキュメントでは、Geese-in-the-Box (旧 Goose-in-the-Box) のインタラクティブ CLI ランチャー (`make menu`)、各エージェントの起動コマンド、高度なオプション、および運用管理コマンドの利用方法について詳しく解説します。

## 1. インタラクティブ CLI ランチャー (`make menu`)

`make menu` コマンドを使用すると、直感的でインタラクティブな CLI ランチャーが起動します。
オプションの組み合わせミス（例：GUI を起動したいのに `--rm` を忘れたり、コマンドを間違えたりすること）を防止するメリットがあります。

- **操作方法**:
  - `↑` / `↓` 矢印キーでメニュー項目を移動します。
  - `Space` キーでオプションのトグル（選択/解除）を行います。
  - `Enter` キーで選択したアクションを決定して実行します。
- **メニュー構成**:
  - **エージェント起動**: Goose、OpenCode、OpenClaw の CLI および GUI モードでの起動を選択できます。
  - **オプション設定**: GPU パススルーの有効化や、コンテナ状態保持（RM=0）などのトグル設定が含まれます。
  - **管理操作**: 全体停止、破棄、ログ・レポート表示、キルスイッチなど、運用に必要な各種コマンドを実行できます。

## 2. エージェント起動コマンド一覧 (CLI vs GUI)

用途やエージェントごとに、ターミナル上で直接対話する CLI モードと、ブラウザから仮想デスクトップを操作する GUI モード（noVNC）が提供されています。

| エージェント | インターフェース | 起動コマンド | アクセス先 |
| :--- | :--- | :--- | :--- |
| **Goose** | ターミナル (CLI) | `make session` | (現在のターミナルで対話) |
| | GUI (noVNC) | `make gui` | [http://localhost:6080/vnc.html](http://localhost:6080/vnc.html) |
| **OpenCode** | ターミナル (CLI) | `make run-opencode` | (現在のターミナルで対話) |
| | GUI (noVNC) | `make run-opencode-gui` | [http://localhost:6081/vnc.html](http://localhost:6081/vnc.html) |
| **OpenClaw 2.0** | ターミナル (CLI) | `make run-openclaw` | (現在のターミナルで対話) |
| | GUI (noVNC) | `make run-openclaw-gui` | [http://localhost:6082/vnc.html](http://localhost:6082/vnc.html) |

※GUI を起動した場合は、対象のアクセス先 URL をブラウザで開いて操作してください。

## 3. 起動オプションの詳細と活用例

コマンド実行時に環境変数を付与することで、コンテナの挙動をコントロールできます。

- ⚡ **GPU パススルー (`USE_GPU=1`)**:
  - 機械学習や CUDA を必要とするコードをエージェントに実行させる場合に有効化します。
  - 例: `USE_GPU=1 make run-opencode-gui`
- 💾 **コンテナ状態保持 (`RM=0`)**:
  - デフォルトではエージェントセッション終了時にコンテナは破棄されます（`--rm` 相当）。
  - `RM=0` を指定すると、セッション終了後もコンテナが保持されるため、`apt` や `pip` 等でインストールした環境を次回の起動時に引き継ぐことができます。
  - 例: `RM=0 make session`
- 🔄 **コンテナ再生成 (`make recreate`)**:
  - 既存のコンテナを一旦破棄し、現在の Docker イメージからクリーンな状態で再作成して起動します。設定変更後や不具合時に便利です。
- 🧹 **完全初期化 (`make clean-all`)**:
  - すべてのコンテナ、孤立したコンテナ、および名前付きボリュームを完全に破棄し、システムを初期状態に戻します。

## 4. 管理・運用コマンドリファレンス

ネットワークの監査やシステムの健全性維持のために、以下の運用コマンドが用意されています。

- **統合コントロールパネル (`make control`)**:
  - GUI ベースのコントロールパネル（ポート 6080 内）を起動します。ホワイトリスト管理や緊急キルスイッチの操作が可能です。
- **リアルタイムログ監視 (Dozzle)**:
  - コンテナの実行ログをブラウザでリアルタイムに確認できます。`http://localhost:8080/` にアクセスしてください。
- **監査ログ・レポート**:
  - `make report`: 現在のネットワークトラフィックの監査レポートを生成して表示します。
  - `make report-watch`: レポートを継続的に監視・自動更新します。
  - `make audit-denied`: 拒否された通信（403 エラー）の一覧を出力します。
- **緊急キルスイッチ**:
  - `make block-all`: エージェントからの全外部通信を即座に遮断します（プロキシ側で全て拒否）。
  - `make unblock`: 通信遮断を解除し、元のホワイトリストルールに戻します。
- **通信遮断テスト (`make test`)**:
  - テストコンテナを立ち上げ、ホワイトリスト外の通信が正しく Squid で遮断されるか、またホワイトリスト内の通信が許可されるかを自動テストします。
