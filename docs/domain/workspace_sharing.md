# ワークスペース共有と協調ワークフロー

Goose-in-the-Box は「AI と人間がシームレスにペアプログラミングを行う」ことを目的に、ワークスペースのリアルタイム同期とパーミッションの統一機構を提供します。

## `./workspace` のバインドマウント

ホストマシンのリポジトリ直下にある `./workspace` ディレクトリは、各エージェントコンテナ内の `/workspace` にバインドマウント（読み書き可能）されています。

```yaml
# docker-compose.yml
volumes:
  - ./workspace:/workspace:rw
```

### リアルタイム同期のメリット
エージェントがコンテナ内で作成・変更したファイル（コード、ドキュメント、生成画像など）は、ホストマシン上のファイルシステムに即座に反映されます。
これにより、以下のような協調ワークフローが可能になります。
1. エージェントがボイラープレートやテストコードを生成する。
2. ホストマシンの VS Code などのエディタで、人間が即座にコードをレビュー・修正する。
3. エージェントに「先ほど私が修正したコードを確認して、次のステップに進んで」と指示を出す。

## UID / GID の統一とパーミッション問題の解決

Docker を用いた開発環境で頻発する「コンテナ内で作成したファイルが root 所有になり、ホストから編集・削除できない」という問題を解決するため、コンテナの実行ユーザーをホストのユーザーに動的に合わせています。

### 仕組み
`docker-compose.yml` にて、環境変数 `${UID:-1000}` および `${GID:-1000}` をコンテナの実行ユーザーとして指定しています。

```yaml
# docker-compose.yml
user: "${UID:-1000}:${GID:-1000}"
```

`Makefile` の各コマンド起動時、ホストマシンのカレントユーザーの ID を取得し、それを環境変数として渡してコンテナを起動します。
これにより、コンテナ内でファイルを作成しても、そのファイルの所有権はホストマシンの操作ユーザーと完全に一致し、パーミッションエラー（Permission Denied）が発生しません。

## 成果物のエクスポート

作業が一段落した場合や、現在のワークスペースの状態をスナップショットとして保存したい場合、`make export-workspace` コマンドを使用します。

```bash
make export-workspace
```

このコマンドは、`./workspace` ディレクトリ全体を `exports/workspace_YYYYMMDD_HHMMSS.tar.gz` の形式で圧縮・保存し、ファイル転送やバックアップを容易にします。
